# Communication-problem casebook

The casebook is indexed by the problem a presentation must solve, not by a
decorative look. Its [machine-readable index](casebook/casebook-index.v1.json)
separates accepted work from planned evidence lanes.

An accepted case must bind an immutable presentation hash, the complete set of
PowerPoint-rendered slide hashes, the original public brief hash, the exact
public teaching-release manifest, and an independent review result. It must
also explain the brief, the AI's authorial choices, the visible outcome, and a
transferable lesson without exposing private material or a sealed answer.

## Current truth

No case is accepted in this initial development slice. The six problem lanes
are explicit intake targets only. They are not examples or endorsements.

The index also records four sanitized development candidates. Their hashes,
review state, limitations, and transferable observations are evidence history,
not reusable deck content. Each candidate predates the current public teaching
release or lacks another acceptance proof. None may be promoted until a fresh
public client replays it against one frozen current manifest and completes the
missing independent and release evidence.

When evidence is accepted, the index may reference it by opaque case ID and
content hashes. It must not embed private artifacts, credentials, hidden
prompts, local locations, or implementation details.
