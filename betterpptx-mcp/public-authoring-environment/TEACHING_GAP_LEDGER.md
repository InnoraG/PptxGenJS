# Developer-to-public teaching-gap ledger

The teaching-gap ledger records when a cold public author needs a reusable
lesson or universal product guarantee that is not yet available through the
public environment.

- [Ledger schema](governance/developer-to-public-teaching-gap-ledger.schema.json)
- [Sanitized development ledger](governance/developer-to-public-teaching-gap-ledger.development.json)
- [Empty development template](governance/developer-to-public-teaching-gap-ledger.template.json)

Every populated entry must cite opaque, hash-bound evidence; classify the gap;
state one generalized lesson; name the public artifact or universal invariant
that should own the correction; define a fresh-context forward test; and bind
the promoted result to a teaching-release manifest.

Do not record private diagnostics, deck-specific answers, credentials, local
locations, or sealed prompt content. A single aesthetic preference is not a
general lesson. A lesson becomes verified only after its target is published
and a fresh public client passes the linked forward test.

The development ledger contains promoted public lessons whose targets already
exist or whose fresh-context tests are pending. Null result and release
bindings are intentional: none of those lessons is marked verified.
