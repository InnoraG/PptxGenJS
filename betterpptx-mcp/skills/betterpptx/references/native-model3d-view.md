# Native Model 3-D view authoring

Treat a Model 3-D View gallery tile as a starting camera treatment, not the authoring ceiling. Discover `model3dViewPreset`: the public catalog exposes 18 exact view families plus 14 typed manual leaves covering camera, transform, viewport, ambient light, and up to three point lights.

Use a native `model3d` object with a public asset handle. Omitted manual fields inherit the selected view; authored camera, transform, light, and viewport fields override only their named components. Set a component or the complete view to `null` for deterministic reset and re-edit. Preserve the native model carrier and its editable relationship; do not replace it with a rendered screenshot.

For a model with one selected motion, opt in with `motionFraming: { mode: "selected-animation" }`. Optional `paddingFraction` (0.02–0.30, default 0.08), `yawDegrees` (−360–360, default 0), and `fovDegrees` (1–120, default 45) control edge space and viewing angle. Angular values use 1/60000-degree steps. This mode frames the selected motion together with the stopped pose; it does not alter model bytes, movement, or playback timing. Do not combine it with a manual `camera`, `trans`, `objViewport`, or `model3dViewPresetId`. Omission or `null` retains ordinary framing.

Motion framing requires an available authorized model handle and an explicit selected scene. Public semantic replay must retain the selected motion ID; private numeric animation selections are not exposed. Unsupported geometry or motion fails explicitly. To change/reset the mode, selected motion, view, or frame size, rebuild with `generate_from_spec` using `replaceDeck` or `createNew`; an in-place shape patch cannot safely reuse stale framing. Export preserves framing intent, not conflicting derived camera controls. Native PowerPoint playback review remains required: sampled framing is not a continuous-time or visual-quality certificate.

Keep structured-partial Office boundaries explicit for field-of-view, lighting, and canonicalized camera values. Validate numeric ranges and point-light cardinality before commit. The proof boundary is fresh public discovery, JSON-spec upload, mutation-free dryRun, five-checkpoint commit/readback, quality, preview, save, upper-bound rejection, package inspection, and PowerPoint reopen/render without private implementation leakage.
