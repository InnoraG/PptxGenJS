# Native table format with typed controls

Treat a table style as a starting treatment, not the authoring ceiling. Discover `tablePreset` before writing a spec: the public catalog exposes seven style families and 38 typed parameters spanning header/total/first/last-column flags, banding, font and alignment, fill, border, margin, column widths, row heights, pagination, per-cell formatting, and cell merge/rowspan controls.

Precedence is deterministic: the selected table style supplies defaults, then explicit `tableOptions` and per-cell `options` replace only their named components. Omitted values retain the selected base. Set a field or component to `null` to reset that component to the table-style/default behavior; rerun dryRun after reset or re-edit.

Use stable semantic names, verified data evidence, and semantic layout regions. Never provide coordinates or private source paths. The proof boundary is fresh discovery, JSON-spec upload, mutation-free dryRun, commit, quality, preview, save, numeric boundary rejection, package inspection, and PowerPoint Open2007/SaveCopyAs/reopen/render. A structured-partial status is an honest Office or pagination boundary, not a reason to invent a hidden control.
