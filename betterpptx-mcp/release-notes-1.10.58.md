# BetterPPTX 1.10.58 — publication allowance persistence

The 1.10.57 public Chat-mode test accepted a complete unchanged issued binding,
compiled the unchanged one-slide fixture at revision 2, and passed strict
validation. Its sole save failed while recording an optional operation ID in
the free-publication event. The after-failure account snapshot remained zero
used, zero reserved, three remaining. No downloadable artifact was returned.
This does not prove rollback of intermediate artifact materialization.

Rolling allowance records now normalize optional metadata at their shared
persistence boundary. Local and distributed reserve/commit/release/replay
paths retain the same identity, reservation fingerprints, limits, windows,
lease expiry, explicit values and atomic accounting. Global database
undefined-field suppression is not enabled. No account reset or entitlement
grant is part of this repair.

The operation and allowance stores share one JSON normalization contract.
An isolated strict-store integration test exercises the actual dispatcher,
unchanged issued quote, native compile, strict validation, save, result replay
and byte retrieval. It verifies one publication event bound to the actual
durable save operation ID. This is local integration evidence, not a real
browser or cloud-provider execution.

Generic unclassified operation failures no longer return provider diagnostics
from stored status records, and uncertain outcomes do not suggest blindly
starting a duplicate mutation with a new key. Typed authoring findings remain
actionable. The original 12-hour file/link boundary and size-based link
fallback are unchanged. Public tool schemas are unchanged.

The next public acceptance step reuses the existing owned revision rather
than generating another deck, under the already approved single zero-charge
publication scope. Local tests and deployment are not a claim of browser
delivery, rendering, reopen/editability review or watched playback.
